# 企业官网设计沟通与落地

从两个真实项目（beiming 深色科技风、souinco 浅色编辑风）沉淀的官网设计工作流与避坑清单。

> **优先级声明**：本技能中的风格参考（尤其是深色科技风的粒子/霓虹方案）若与项目 CLAUDE.md 的视觉设计系统、内容红线、交互调性等约定冲突，一律以 CLAUDE.md 为准。例如 Arxhe 官网项目要求低饱和配色、克制动效、禁止粒子动画与渐变霓虹，即不可套用深色科技风方案。

## 核心工作流（按序执行）

### 1. 调研先行
- 抓取线上原站**全部页面**真实内容（用 sitemap 发现 URL：`/wp-sitemap.xml` → page-sitemap），文案、数据、联系方式全部以线上为准，不杜撰。
- 找齐品牌资产：logo SVG（提取准确色值）、公司介绍资料，通常在企业 docs/ 目录。
- 若涉及重构，先弄清线上技术栈与部署环境（SSH 上去看），写分析报告。

### 2. 双风格模板提案（不要直接做整站）
- 做**两个可直接打开查看的静态 HTML 模板**（一深一浅通常最稳），页面结构与线上一致，只做样式翻新。
- 模板要中英双语可切换，内容用线上真实文案。
- 让用户明确选定一个方向后再进入实现。

### 3. Hero 先行，逐轮定稿
- Hero 是沟通重心，先做 Hero 并迭代到用户明确说"定稿"，再向整站铺开同风格。
- 为设计元素建立**寓意体系**并与用户确认（例：souinco 齿轮=运输稳定可靠；beiming 鲲鱼=供应链广阔流动）。用户认同寓意后，后续调整都围绕寓意沟通，不围绕抽象审美。
- 从 logo 造型提取 Hero 母题（logo 有齿轮就做齿轮，有鲲鱼就做鲲鱼）。

### 4. 整站铺开 + 内容对齐
- 子页面与首页共享组件（PageHeader/Reveal/导航/页脚），风格严格一致。
- 与线上全站逐页 diff，补齐缺失内容（导航项、团队、企业文化、行业分类、版权信息），差异处主动向用户说明取舍。

### 5. 每轮记录 + 及时部署
- 每轮沟通写 `claude/session-XX-主题.md`（用户反馈、改动、教训），项目根目录维护 CLAUDE.md 总方案。
- 尽早部署可公开访问的预览（Vercel CLI `vercel --yes --prod`），老板演示不依赖本地环境。

## 避坑清单（两项目实测教训）

### SVG / 图形
- SVG 装饰元素默认 fill 是黑色——**必须显式 `fill:none`**，否则浅色背景上出现黑色实心块。
- 机械图形（如齿轮啮合）不能"看起来差不多"，必须按模数/节圆/相位真实计算：中心距=节圆半径和、转速比=齿数反比、相位使齿对槽。
- 文字标签防遮挡：`textAnchor="middle"` 对齐锚点 + `paint-order:stroke` 背景色描边光晕。
- 布局调整时**删干净旧元素**再验证——残留旧元素被用户发现过多轮。

### 动效
- 全页面动效统一"心跳"：各动画周期取同一基准值的整数比（如航线 12s = 齿轮 72s 的 1/6）。
- 循环动效要双层错位（相位错半周期），前一波未消完后一波已出发，无死区。
- SMIL animateMotion 带 begin 延迟的元素，等待期间会停在 SVG 原点（0,0）形成杂点——初始 opacity=0 并用同步 animate 驱动透明度。

### 色彩与按钮
- 浅色背景的"空感"用低透明度网格/水印填充，不要堆砌内容；深色背景用线条网格同样有效。
- 交互色收敛在品牌色深浅谱系：tint（浅底）→ brand → brand-dark（hover 加深），不引入色系外的颜色。
- 主/次按钮 hover 态必须可区分（主按钮 hover 加深，次按钮 hover 浅蓝底），两个按钮不能撞色。
- 语言切换等辅助按钮也用品牌蓝描边体系，不要用默认黑灰色。

### 协作
- 用户截图反馈先逐像素定位（坐标→SVG 坐标系换算），再改代码。
- 浏览器和 dev server 缓存重，回复时提醒 Ctrl+F5；favicon 缓存尤其顽固。
- 验证后必须停掉临时 dev server（netstat 找 PID → taskkill //PID x //T //F），不留后台进程。
